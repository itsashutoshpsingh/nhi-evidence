- 2026-11-14. Novelty and overlap search; Graph, Entra and OWASP docs read at pinned commits (`scripts/fetch_refs.py`). Firecrawl credits ran out midway; the rest of the doc reading used raw files from the docs repositories at fixed commits.
- 2026-11-14. First run of the 14 checks on the seeded tenant: 15 of 15 expected findings, 0 extra, 5 suppressed (3 Microsoft first-party, 2 allowlisted vendor).
- 2026-11-14. First run of 42 single-change mutations: 4 did not match my written expectations. In all 4 the tool was right and my expectation was incomplete: a data permission on an app whose owner is not an admin is also a credential-control path (M06a), and any path that reaches "every application" also reaches the allowlisted vendor app that holds Mail.Read (M06c, M13b, M13c). Expectations corrected; recorded in docs/what-went-wrong.md.
- 2026-11-14. First synthetic tenants (n=100, 1000): 17 to 23 unexpected C04 expired_present findings per 1,000. Cause: my generator gave background web apps secrets that started up to 60 days ago but lasted 30, so they had already expired. The check was right; the generator was not clean. Fixed by drawing the start date inside the lifetime.
- 2026-11-14. Code mutation run 1 (oracle: seeded, clean, each issue alone, 42 fixture mutations, three n=100 synthetic tenants; compares finding keys only): 170 of 212 mutants killed. Survivors fall into three groups: severity and evidence text the oracle never compared; boundary cases no fixture sits on (exactly 90 days, an app with no service principal, a grant on a non-Graph API, a SAML signing certificate on a third-party service principal); and graph edge guards that only tests/test_graph.py exercises, which the oracle did not run.
- 2026-11-14. Code mutation run 2, with a stronger oracle (the whole pytest suite plus a golden copy of every finding record on the seeded tenant and three 300-identity synthetic tenants): 193 of 212 killed. I then added look-alike controls and mutations for the boundaries no fixture sat on (an app with no service principal; a grant on a non-Graph API; a SAML signing certificate on a third-party service principal; a multi-tenant app registered here; last sign-in exactly 90 days ago; an app created exactly 90 days ago; scoped and tenant-wide Cloud Application Administrator on an owned app; service-principal owners with and without permission to edit apps; a deleted service account) and two graph tests (severity by hop count; the 10-path cap). Writing those exposed one real defect: check 13 treated disabled service principals as targets, although they cannot sign in; fixed. Two redundant expressions were deleted rather than tested (`pat.count(":") >= 1` after `startswith("repo:")`, and a `/ 86400` replaced by a timedelta comparison). Final run: 206 of 208 killed; the two survivors are equivalent on any data the checks can receive (docs/what-went-wrong.md).
